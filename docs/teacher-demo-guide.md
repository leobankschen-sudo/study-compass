# 《知序》教师演示与答辩指南

项目全称：基于大模型的个性化学习进度与智能复盘系统。

## 一、演示前准备

1. 确认 MySQL 8 已启动。
2. 在项目根目录执行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
   ```

   按提示输入本机 MySQL 密码和 DeepSeek API Key。输入内容不可见，也不会写入项目文件。

3. 另开一个终端启动前端：

   ```powershell
   cd frontend
   npm run dev -- --host 127.0.0.1 --port 5173
   ```

4. 浏览器打开 `http://127.0.0.1:5173/`。
5. 演示账号：`demo_user`，密码：`Study2026`。
6. 演示前先确认“智能复盘”页面能看到历史报告。现场网络不稳定时，直接展示历史报告，不必临时等待模型生成。

## 二、建议的 7 分钟演示顺序

### 0:00—0:40 登录与项目定位

讲解词：这是一个围绕“目标—任务—学习记录—AI 复盘—下一步行动”形成闭环的学习管理系统，不是简单给聊天接口套一层页面。

操作：登录系统，指出统一的顶部导航和当前用户信息。

### 0:40—1:30 首页看板

操作：进入首页，展示目标进度、待办任务、累计时长和近期学习数据。

讲解词：看板不是静态样例，它来自当前登录用户在 MySQL 中的真实业务数据。

### 1:30—3:00 核心业务闭环

操作：依次进入“目标”“任务”“记录”，演示新增或编辑一条数据；完成一项任务后补充一条学习记录。

讲解词：三类数据彼此关联，任务属于目标，学习记录可以关联任务，后续 AI 分析直接使用这些数据。

### 3:00—5:15 AI 智能复盘

操作：进入“智能复盘”，先展示生成前的证据摘要，再打开已有复盘报告；展示洞察、证据和行动建议，最后将一条建议转成任务。网络稳定时再现场生成一次学习计划。

讲解词：系统把真实学习数据组织为受约束的上下文，要求模型输出结构化 JSON；后端完成校验、容错解析和持久化。报告中的行动建议还能回到任务系统，因此 AI 输出真正进入业务流程。

### 5:15—6:10 资料库

操作：按类型和目标筛选资料，新增一条官方文档链接，展示编辑、访问来源和删除。

讲解词：资料库解决学习材料散落的问题，同时保留来源、标签和目标关联，为未来接入 RAG 或文档解析预留数据基础。

### 6:10—7:00 工程与安全

操作：简要展示 Git 提交历史、实验清单和项目目录。

讲解词：前后端分离，使用 Vue 3、TypeScript、Spring Boot、MyBatis 和 MySQL；登录采用 JWT，密码使用 BCrypt；所有业务查询都限定当前用户。DeepSeek Key 只存在于后端进程环境变量，不会进入浏览器和 Git。

## 三、最值得强调的五个亮点

1. **AI 与真实业务数据结合**：不是通用聊天框，而是使用目标、任务、完成情况和学习时长生成个性化复盘。
2. **“证据—判断—行动”闭环**：先展示分析依据，再给洞察与建议；建议可以一键转为任务，形成下一轮学习计划。
3. **结构化、可持久化的 AI 输出**：后端约束模型返回 JSON，并处理代码围栏、字段差异、空响应、超时和限流等异常；报告保存后可追溯。
4. **隐私与数据隔离**：API Key 不下发前端；JWT 鉴权、BCrypt 密码哈希、按当前用户校验资源归属；用户还可以关闭 AI 个性化。
5. **完整但克制的产品范围**：顶部导航统一、视觉风格一致，覆盖学习主链路和资料归档；主动舍弃社交、OCR、语音等偏题功能，把完成度放在功能数量之前。

## 四、老师常问的问题与参考回答

### 为什么选择 DeepSeek？

它提供与常见聊天补全协议兼容的接口，接入成本和课程演示成本较低。项目把地址、模型和 Key 都放在配置层，未来更换模型不需要重写前端和核心业务。

### 怎样减少 AI 幻觉？

只发送系统已有的学习证据，提示词限定任务和输出结构；页面同时展示证据摘要，让用户能够核对。AI 建议不会自动修改核心数据，必须由用户确认后才转成任务。

### API Key 安全吗？

Key 只由 Spring Boot 后端从环境变量读取，前端代码、网络响应和 Git 仓库都不包含 Key。公开展示或提交项目前应轮换曾经暴露过的 Key。

### 如何保证不同用户看不到彼此的数据？

后端从 JWT 获取当前用户 ID，查询和增删改都带用户条件，并在修改或删除前检查资源归属；不能只依赖前端隐藏。

### AI 返回的格式不稳定怎么办？

请求端启用 JSON 输出并关闭不需要的思考内容；服务端有兼容解析和字段校验。超时、鉴权失败、限流、空响应或非法 JSON 都会返回可理解的错误，并且不会保存无效报告。

### 为什么使用 MyBatis？

课程项目需要直观看到表结构、关联条件和用户隔离 SQL。MyBatis 让 SQL 可控、便于讲解，也适合后续增加统计查询。

### 数据库有哪些核心表？

用户、学习目标、学习任务、学习记录、用户偏好、AI 报告和学习资料，共七类核心数据。

### 项目目前的不足是什么？

目前是本地课程演示版本，缺少公网部署、自动化浏览器端到端测试，以及针对真实文档内容的向量检索。下一步会优先补测试和部署，再考虑 RAG，而不是盲目增加功能。

### 五个实验如何体现？

仓库 `docs` 目录分别保存实验一至实验五的验收清单；Git 中保留功能分支和规范化提交，最终实验报告可以基于这些代码、截图和提交记录统一撰写。

## 五、现场故障的备用方案

- DeepSeek 网络波动：展示已保存的两份历史报告，重点演示报告结构和“一键转任务”。
- 前端无法打开：确认前端终端仍在运行，并访问 `http://127.0.0.1:5173/`。
- 登录失败：确认后端 `http://127.0.0.1:8080/` 已启动，并重新执行本地启动脚本导入演示数据。
- 不要在投屏时展示或口述 MySQL 密码、DeepSeek API Key、JWT Secret。

## 六、正式提交前仍需完成
